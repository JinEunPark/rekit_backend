# 철거 가전 직거래 플랫폼 MVP 요구사항 정의서

## 1. 프로젝트 개요

### 1.1 배경

철거 현장에서 나오는 사용 가능한 가전 제품(냉장고, 세탁기, TV, 에어컨 등)을 폐기하지 않고 저렴한 가격에 재판매하는 온라인 플랫폼.

### 1.2 목표 (MVP)

- 판매자(철거업자)가 가전 제품을 등록하고 판매할 수 있는 채널 확보
- 구매자가 안심하고 중고 가전을 구매할 수 있는 신뢰 기반 거래 환경 제공
- 결제 → 배송 → 수령까지 이어지는 최소 거래 흐름 완성

### 1.3 페르소나

| 페르소나 | 설명                                                   |
| -------- | ------------------------------------------------------ |
| 구매자   | 자취생, 신혼부부, 고시원/원룸 운영자, 소상공인, 사무실 |
| 판매자   | 철거업자(친구) — MVP 단계에서는 단일 판매자로 운영     |
| 관리자   | 플랫폼 운영자 (판매자와 동일인이거나 별도)             |

### 1.4 MVP에서 제외하는 것 (Out of Scope)

- 다중 판매자(셀러) 입점 시스템
- 채팅/문의 실시간 기능 (이메일 또는 전화 안내로 대체)
- 후기/평점 시스템 (1차 출시 후 추가)
- 쿠폰/프로모션 시스템
- 모바일 앱 (모바일 웹 반응형으로 대응)
- 복잡한 추천/검색 알고리즘

## 2. 핵심 기능 요구사항

### 2.1 구매자 기능

#### 2.1.1 회원

- 이메일 회원가입 / 로그인
- 소셜 로그인 (카카오, 네이버) — 한국 사용자 편의성
- 비밀번호 재설정
- 회원 정보 수정 (이름, 연락처, 배송지)
- **휴대폰 SMS 인증** (회원가입 시 필수) — 봇/중복 가입 방지
- **본인인증** (실명·생년월일·CI/DI) — 첫 주문 직전 1회 진행, 이후 CI 저장 후 재사용
  - 미성년자(만 14세 미만) 가입 차단
  - 차지백/사기 결제 분쟁 시 신원 확인용
  - 인증 만료 시(개명·번호 변경 등) 재인증 요청 플로우 필요

#### 2.1.2 상품 탐색

- 카테고리별 조회 (냉장고/세탁기/TV/에어컨/주방가전/기타)
- 키워드 검색
- 정렬 (최신순/낮은가격순/높은가격순)
- 필터 (가격대, 상태 등급, 브랜드)

#### 2.1.3 상품 상세

- 다중 이미지 (필수: 정면/측면/상태 흠집 부위)
- 제품 정보: 브랜드, 모델명(있으면), 연식(추정), 사이즈, 무게
- **상태 등급**: A(거의 새 것) / B(사용감 있음) / C(흠집 많음, 동작은 OK)
- **동작 보증 여부** 명시
- **A/S 불가** 명시 (법적 분쟁 방지)
- 배송 가능 지역 / 배송 방식 안내

#### 2.1.4 장바구니

- 상품 추가/삭제/수량 변경
- 장바구니 상품 목록 조회 (비로그인 시 세션, 로그인 시 DB 저장)

> ⚠️ 가전은 보통 1개 단위 구매라 장바구니가 필수는 아니지만 확장성 차원에서 포함

#### 2.1.5 주문 / 결제

- 주문서 작성: 배송지, 연락처, 배송 메모
- 배송비 자동 계산 (무게/사이즈/지역 기반)
- 결제 수단: 신용카드, 계좌이체, 카카오페이, 네이버페이, 토스
- 결제 완료 후 주문 확인 페이지 + 이메일/SMS 발송

#### 2.1.6 주문 관리

- 주문 내역 조회 (목록 / 상세)
- 주문 상태 확인: 결제완료 → 상품준비중 → 배송중 → 배송완료
- 배송 추적 (송장번호 클릭 시 배송 조회 화면)
- 주문 취소 (결제완료 ~ 상품준비중 단계까지만 가능)
- 환불 요청 (반품 정책에 따라 — 단순 변심 vs 상품 하자 구분)

---

### 2.2 관리자 기능

#### 2.2.1 대시보드

- 오늘의 주문 수 / 매출
- 처리 대기 주문 수 (배송 준비 필요)
- 재고 부족 알림 (재고 0인 상품)
- 최근 7일 매출 그래프

#### 2.2.2 상품 관리

- 상품 등록 (이미지 다중 업로드, 카테고리, 상태 등급, 가격, 사이즈/무게, 상세 설명)
- 상품 수정 / 삭제 / 판매중지(임시 비공개)
- 재고 수량 관리 (보통 1개씩이지만 동일 모델 여러 개 입고될 수 있음)
- 일괄 등록(CSV) — 우선순위 낮음, 시간되면

#### 2.2.3 주문 관리

- 주문 목록 (상태별 필터링)
- 주문 상세 조회
- **배송 정보 입력** (택배사 선택, 송장번호 입력) → 자동으로 "배송중" 상태 전환
- 주문 상태 수동 변경 (배송완료 처리 등)
- 주문 취소 / 환불 처리

#### 2.2.4 회원 관리

- 회원 목록 조회 / 검색
- 회원 상세 (가입일, 주문 이력)
- 회원 차단/제재 (악성 사용자 대응)

#### 2.2.5 정산 / 매출

- 기간별 매출 조회
- 결제 수단별 매출 분석
- CSV 내보내기

### 2.3 배송 기능 상세

#### 2.3.1 배송 방식

1. **일반택배** — 소형 가전 (전자레인지, 청소기 등)
2. **화물택배** — 대형 가전 (냉장고, 세탁기, 에어컨)
3. **직접 배송** — 특정 지역 한정 (서울/경기 등 — 친구가 철거 차량으로 직접 배송 가능한 경우)

#### 2.3.2 배송 상태 조회

- 송장번호 + 택배사 정보로 배송 상태 실시간 조회
- **연동 추천**: 스마트택배 API (sweet tracker) 또는 굿스플로 API
  - 한 번 연동으로 모든 택배사 추적 가능
  - 무료 플랜 있음 (호출량 제한)
- 직접 배송의 경우 관리자가 수동으로 상태 업데이트

#### 2.3.3 배송 상태 흐름

```
결제완료 → 상품준비중 → 배송중(송장번호 등록) → 배송완료
                        ↓
                   (실시간 추적)
```

### 2.4 본인인증 / 신원 확인

#### 2.4.1 인증 단계 구분

| 단계 | 시점         | 방식                             | 목적                     |
| ---- | ------------ | -------------------------------- | ------------------------ |
| 1차  | 회원가입     | SMS 인증 (휴대폰 번호 소유 확인) | 봇/중복 가입 방지        |
| 2차  | 첫 주문 직전 | 본인인증 (이름+생년월일+CI/DI)   | 신원 확인, 미성년자 차단 |
| 3차  | 결제 시      | 카드사 본인확인 (PG사가 처리)    | 부정결제 차단            |

> 회원가입 시 본인인증을 강제하면 가입 전환율이 크게 떨어짐 → "주문 직전" 1회로 충분

#### 2.4.2 본인인증 서비스

- **추천**: 토스페이먼츠 본인인증 모듈 (PG와 같은 계약으로 통합 가능)
- **대안**: NICE평가정보, KCB, 드림시큐리티
- 인증 결과로 받은 **CI(Connecting Information, 88바이트)** 를 DB에 저장 → 재가입 차단/신원 매칭에 활용
- **DI(Duplicate Information)** 도 함께 저장 → 동일 사이트 내 중복 가입 차단

#### 2.4.3 데이터 보관 정책

- CI/DI는 단방향 해시값이지만 개인정보로 분류 → **암호화 저장** 필수
- 회원 탈퇴 시 CI/DI 즉시 파기 (단, 분쟁 대응 위해 거래 정보는 5년 보관 — 전자상거래법)
- 본인인증 로그(인증 시각, 결과)는 별도 테이블에 보관

## 3. 비기능 요구사항

### 3.1 성능

- 페이지 로딩 3초 이내 (3G 환경 기준)
- 상품 이미지 lazy loading + WebP 변환
- 검색 결과 1초 이내 응답

### 3.2 보안

- HTTPS 필수
- 비밀번호 bcrypt 해싱
- 결제 정보는 PG사에 위임 (자체 저장 금지 — PCI-DSS 회피)
- 개인정보 암호화 저장 (전화번호, 주소, **CI/DI**)
- 관리자 페이지 IP 화이트리스트 또는 2FA
- JWT Access Token 짧게(15분~1시간), Refresh Token은 HttpOnly 쿠키
- API Rate Limiting (FastAPI `slowapi` 등)

### 3.3 호환성

- 모바일 반응형 필수 (모바일 트래픽 70%+ 예상)
- 지원 브라우저: Chrome, Safari, Edge 최신 2개 버전
- iOS Safari, Android Chrome 최신 2개 버전

### 3.4 SEO (Vue SPA 고려사항)

- Vue는 기본적으로 SPA → 검색엔진 노출이 약함
- **상품 상세 페이지**는 SEO가 중요 (네이버/구글 유입)
- 대응 옵션:
  - (권장) **Nuxt 3로 전환** — Vue 기반 SSR/SSG 프레임워크
  - (대안) `vite-plugin-ssr` 또는 prerendering 적용
  - (최소 대응) `vue-meta`로 메타태그 동적 변경 + sitemap.xml 생성

### 3.5 법적 / 정책

- **통신판매업 신고** 필요 (관할 구청)
- **사업자등록증** 필요
- 개인정보처리방침 / 이용약관 / 환불 정책 페이지
- **중고 가전 특성상 A/S 불가, 단순 변심 반품 제한** 명시 (대형 가전 반송비 부담 큼)
- 상품 하자 시 7일 이내 환불 가능 (전자상거래법 준수)

## 4. 데이터 모델 (간략)

```
User
  - id, email, password_hash, name, phone, role(USER/ADMIN), created_at

  - identity_verified_at     # 본인인증 완료 시각
  - ci (encrypted)           # 88바이트, 암호화 저장
  - di (encrypted)           # 64바이트, 동일사이트 중복가입 차단용

  - id, user_id, provider(toss/nice/kcb), result(SUCCESS/FAIL)
  - request_id, verified_at, created_at

Address
  - id, user_id, recipient, phone, zipcode, address1, address2, is_default

Product
  - id, title, description, category, brand, model_name, year_estimate
  - condition_grade (A/B/C), warranty_works(boolean)
  - price, original_price
  - weight_kg, width_cm, depth_cm, height_cm
  - stock, status(ACTIVE/INACTIVE/SOLD_OUT)
  - created_at, updated_at

ProductImage
  - id, product_id, url, sort_order

CartItem
  - id, user_id, product_id, quantity

Order
  - id, order_number, user_id, total_amount, shipping_fee
  - status (PAID/PREPARING/SHIPPING/DELIVERED/CANCELLED/REFUNDED)
  - recipient_name, recipient_phone, zipcode, address1, address2, memo
  - created_at, paid_at

OrderItem
  - id, order_id, product_id, product_title_snapshot, price_snapshot, quantity

Payment
  - id, order_id, pg_provider(toss/kakao/naver), pg_tid
  - method(CARD/BANK/KAKAO_PAY/...), amount, status, paid_at

Shipment
  - id, order_id, carrier, tracking_number
  - status, shipped_at, delivered_at, last_tracked_at
```

### 5.2 프로젝트 구조 (참고)

**Frontend (Vue)**

```
src/
├── api/              # axios 인스턴스 + API 호출 함수
├── components/       # 공통 컴포넌트
├── views/            # 페이지 단위 (구매자)
├── views/admin/      # 관리자 페이지
├── stores/           # Pinia stores (auth, cart, order)
├── router/           # Vue Router (gard로 인증/관리자 분기)
├── composables/      # 재사용 로직 (useAuth, useCart 등)
└── types/            # TypeScript 타입 정의
```

**Backend (FastAPI)**

```
app/
├── api/v1/
│   ├── auth.py
│   ├── products.py
│   ├── orders.py
│   ├── payments.py
│   ├── shipments.py
│   ├── verifications.py   # 본인인증
│   └── admin/             # 관리자 전용 엔드포인트
├── core/             # 설정, 보안(JWT), 의존성
├── models/           # SQLAlchemy 모델
├── schemas/          # Pydantic 스키마 (Request/Response)
├── services/         # 비즈니스 로직 (결제, 배송 등 외부 연동)
├── crud/             # DB 접근 레이어
└── workers/          # Celery 태스크
```

### 5.3 FastAPI 운영 시 주의점

- **CORS 설정** 필수 (Vue 개발 서버 ↔ FastAPI)
- 동기 라이브러리(예: 일부 SDK) 사용 시 `run_in_threadpool` 또는 워커 분리
- 결제·본인인증 콜백은 **멱등성 보장** (중복 요청 방어)
- 관리자 API는 별도 라우터 + `Depends(get_current_admin)` 가드
- 운영 배포는 `gunicorn -k uvicorn.workers.UvicornWorker` 권장

## 6. 개발 우선순위 (MVP 단계별)

### Phase 1 (최소 동작)

- 회원가입/로그인 + **SMS 인증**
- 상품 등록(관리자) / 조회(구매자)
- **본인인증 (주문 직전)**
- 주문 + 결제
- 관리자 주문 확인 + 송장번호 입력
- 배송 추적 (단순 송장 링크 연결만으로 시작 가능)

### Phase 2 (운영 안정화)

- 배송 추적 API 연동 (자동 상태 업데이트)
- 주문 취소/환불 플로우
- 관리자 대시보드 통계
- SMS/이메일 알림 자동화

### Phase 3 (확장)

- 후기 시스템
- 직접 배송 지역 관리
